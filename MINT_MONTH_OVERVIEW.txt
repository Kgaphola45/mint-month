1. EXECUTIVE SUMMARY & PHILOSOPHY
================================================================================
Mint Month is a modern, privacy-first personal finance engine custom-tailored
for South African earners (ZAR / R). Unlike traditional corporate budgeting apps
that focus on historical guilt and endless transaction tagging, Mint Month is
designed around an editorial, calm, magazine-like interface that prioritizes
one primary question every single day:

    "How much guilt-free money can I spend today without starving before payday?"

The system automatically rings-fences recurring debit orders (rent, medical aid,
vehicle financing, insurance, gym), debt instalments, and savings vault
allocations (emergency funds, Stokvel, holiday funds) away from the user's
take-home pay, dividing only true disposable income across remaining cycle days.

Key Philosophy Pillars:
- Zero Guilt: No punitive red alerts; clear, actionable math.
- Local South African Context: Built around 25th / monthend payday schedules,
  Stokvel savings goals, SASSA/SARS awareness, debit order clearance schedules,
  and local merchants (Checkers, Woolworths, Pick n Pay, Sixty60, Engen).
- Local-First Resilience: Operates offline with instant optimistic client-state
  updates (Zustand + IndexedDB/localStorage), auto-syncing seamlessly to Supabase
  PostgreSQL when network is available.
- Privacy & Granular Control: Every user's financial records are locked behind
  PostgreSQL Row Level Security (RLS). Users own their data and can export it as
  standard CSV/JSON or purge their account with one click.

3. ARCHITECTURE & DATA FLOW (LOCAL-FIRST + SUPABASE CLOUD)
================================================================================
Mint Month uses a hybrid Local-First architecture:

1. Optimistic Local Mutations:
   When an expense is logged or a budget is updated, Zustand updates the
   in-memory React state instantly (0ms latency) and persists to localStorage
   and IndexedDB. The UI never hangs on loading spinners for common actions.

2. Cloud Synchronization Pipeline:
   If the user is logged into Supabase:
   - On initial login/load: The app fetches remote records from PostgreSQL and
     merges them into local state.
   - On write: Mutations emit parallel async writes to Supabase tables
     (`transactions`, `budgets`, `debit_orders`, `debt_contracts`, `users`).
   - Preferences Sync: Custom categories, monthly salary overrides, paydayDay,
     and UI preferences are mirrored into the `preferences` JSONB column of
     `public.users`.

3. Offline-Safe Fallback:
   If the user travels, loses connectivity, or loads the app in an area with
   load shedding / poor signal, the entire app remains fully functional. When
   connectivity returns, the cloud layer accepts latest local modifications.

5. DATABASE SCHEMA & SECURITY (POSTGRESQL & RLS)
================================================================================
All data is stored in PostgreSQL tables managed via Supabase, protected by Row
Level Security:

1. `public.users`
   - `id` (UUID, Primary Key, references auth.users.id ON DELETE CASCADE)
   - `email` (TEXT, Unique)
   - `full_name` (TEXT)
   - `role` (TEXT, default 'standard', 'superuser')
   - `preferences` (JSONB: holds custom categories, salary overrides, paydayDay)
   - `created_at` (TIMESTAMPTZ)
   - `updated_at` (TIMESTAMPTZ)

2. `public.transactions`
   - `id` (UUID, Primary Key)
   - `user_id` (UUID, references auth.users.id)
   - `amount` (NUMERIC)
   - `category` (TEXT)
   - `description` (TEXT)
   - `date` (DATE)
   - `payment_method` (TEXT)
   - `is_cleared` (BOOLEAN)
   - `receipt_url` (TEXT, optional)

3. `public.budgets`
   - `id` (UUID, Primary Key)
   - `user_id` (UUID, references auth.users.id)
   - `category` (TEXT)
   - `cap` (NUMERIC)
   - `month` (TEXT, e.g. '2025-05')

4. `public.debit_orders`
   - `id` (UUID, Primary Key)
   - `user_id` (UUID, references auth.users.id)
   - `name` (TEXT)
   - `amount` (NUMERIC)
   - `due_day` (INTEGER, 1-31)
   - `category` (TEXT)
   - `cleared` (BOOLEAN)
   - `previous_amount` (NUMERIC, for price-hike alerts)

5. `public.debt_contracts`
   - `id` (UUID, Primary Key)
   - `user_id` (UUID, references auth.users.id)
   - `name` (TEXT)
   - `creditor` (TEXT)
   - `total_principal` (NUMERIC)
   - `remaining_balance` (NUMERIC)
   - `monthly_instalment` (NUMERIC)
   - `interest_rate` (NUMERIC)
   - `due_day` (INTEGER)

6. `public.password_resets`
   - `id` (UUID, Primary Key)
   - `email` (TEXT)
   - `otp_hash` (TEXT, bcrypt hash)
   - `expires_at` (TIMESTAMPTZ, 15 min expiry)
   - `created_at` (TIMESTAMPTZ)

Row Level Security Rule:
CREATE POLICY "Users can only view and manage their own data"
  ON public.<table_name>
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

6.1. AUTHENTICATION, ONBOARDING & SECURITY
--------------------------------------------------------------------------------
- Full Registration & Login: Email and password authentication with instant
  session management and password hashing via Supabase Auth.

  * 15-minute strict expiration window with rate-limiting.
- Account Deletion & Data Wiping: Standard users can erase their account and all
  associated transactions with a single confirmed action.

6.2. SAFE-TO-SPEND DAILY ENGINE & PAYDAY CYCLE PLANNING
--------------------------------------------------------------------------------
- Real-Time Daily Allowance: Calculates the exact amount of money the user can
  safely spend each day until the next payday.
- Strict Quarantine Logic:
  * Formula: Safe-to-Spend = (Net Take-Home Pay - Upcoming Debit Orders
                              - Pending Debt Instalments - Savings Vault Ringfences
                              - Variable Expenses Already Cleared) / Remaining Days.
- Visual Velocity Dial: An interactive circular gauge that shifts from calm sage
  green to editorial terracotta if spending velocity exceeds daily pace.
- 1-Click Salary & Payday Editor: Accessible directly from the dashboard meter,
  the user menu, or the profile drawer. Users can update their monthly take-home
  amount and payday day (1st-31st) with instant recalculation.

--------------------------------------------------------------------------------
6.3. WHAT-IF PAYDAY RUNWAY SIMULATOR
--------------------------------------------------------------------------------
- Real-Time Zero-Spend Projection: Answers "If I don't spend a single cent on
  unplanned items from today, how much cash will I land on payday with?"
- Scenario Sliders: Allows the user to simulate:
  * Reducing daily spend by 20%, 50%, or 100%.
  * Adding an unexpected one-off expense (e.g. R850 tyre puncture).
  * Receiving an unexpected cash inflow (e.g. freelance work, bonus).
- Visual Runway Chart: Displays projected daily bank trajectory through payday.

--------------------------------------------------------------------------------
6.4. "CAN I AFFORD IT?" PURCHASE DECISION SIMULATOR
--------------------------------------------------------------------------------
- Pre-Purchase Calculator: Allows users to test a potential expense (e.g. R1,200
  dinner or jacket) BEFORE swiping their card.
- Impact Evaluation: Shows precisely how the expense reduces daily Safe-to-Spend
  for every remaining day in the month.
- Decision Verdicts:
  * "Comfortable": Fits within the daily surplus without pinching future days.
  * "Tight": Drops daily allowance below safe minimum threshold.
  * "Critical": Breaches debit order ringfences; prompts postponing purchase.

--------------------------------------------------------------------------------
6.5. RECURRING BILLS & DEBIT ORDER TIMELINE (WITH PRICE-HIKE DETECTION)
--------------------------------------------------------------------------------
- Visual Timeline View: Chronological list of all debit orders mapped against
  their respective day of the month (e.g. 1st, 15th, 25th, 28th).
- Cleared vs. Pending Tracking: Single-click toggle to mark a debit order as
  cleared once the bank notification arrives.
- Automatic Ring-Fencing: Uncleared debit orders are subtracted from Safe-to-Spend;
  cleared debit orders are marked off without double-counting.
- Price-Hike Detection & Warning Flags:
